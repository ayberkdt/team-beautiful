# R_audit_2026-11-04 — evidence audit of [D]/[D-ag] values in `04_Venus/docs/25_lugus_venus_rotorcraft.md`

**Who / when:** an audit subagent (Claude Opus 5.5), 4 Nov 2026, working read-only on docs/25 and the notes. This
file is the only thing written in the repo. Scratch files are outside the repo: `D:\tmp_ideathon\venus\audit\`
(`candidates.py`, page renders).

**Method.**
1. I listed every numeric value tagged [D] or [D-ag] in docs/25. That gave 166 candidates: §3 table cells, the
   §5.1 Dutta-table cells and each separate tagged statement. The list and the draw are in
   `D:\tmp_ideathon\venus\audit\candidates.py` (`python -I candidates.py` reproduces the draw). Each candidate has
   a category:
   - ATM: Pioneer Venus T/p/ρ
   - WIND: DLBI/VEGA/VEX
   - ENTRY: Dutta Table 1, SP-461, Siddiqi
   - ROTOR: Ingenuity/MSH/Dragonfly
   - OTHER
2. Draw: `random.seed(20261104)`, then `random.shuffle` of the candidate indices. In shuffled order I took the
   first 3 ATM, 2 WIND, 3 ENTRY and 3 ROTOR items, then filled up to 15 with the next items in shuffled order. On a
   first pass Syal 2008 was filed as ROTOR. I moved it to OTHER before the final draw because it is not an
   Ingenuity/Dragonfly/MSH figure.
3. For each value I opened the original source and ignored the note:
   - PDS CSV/TAB rows: parsed with numpy.
   - PDFs: text from PyMuPDF; figures rendered and read by eye.
   - Web pages: curl, or WebFetch where curl was refused.

   Atmosphere means are 4-probe means of linear interpolation between adjacent raw rows. Winds:
   west = col 3 − col 5 of the DLBI table. Altitude comes from the same probe's LAS/SAS `grt_sec → alt` columns.

**Verdicts:**
- **MATCH**: the value is in the source as written.
- **ROUNDED-OK**: the value is the source value rounded, or read off a plot within reading accuracy.
- **CONTEXT-DIFFERENT**: the number is supported, but its condition or attribution differs.
- **MISMATCH**: the source gives a different value.
- **SOURCE-UNAVAILABLE**: the source could not be read.

None of the sampled values is fabricated. The PDS-derived values were checked against the raw rows, and T/p/ρ
reproduce exactly. The problems are with the method behind some numbers:
- **Wind column:** bin means drop probes without saying so (#4).
- **DLBI coverage:** the stated altitude range is wider than the data (#7).
- **Representative value:** one value is shown as if it were a table entry (#14).
- **Attribution:** one test is credited to the wrong vehicle (#6).

## Observations outside the sample (checked here, not counted above)

- **§3 table, T/p/ρ columns (all 5 rows):** recomputed from the raw LAS/SAS rows with 4-probe linear interpolation.
  T means: 74.75 / 46.62 / 25.99 / −2.06 / −15.40 °C. p: 1.029 / 0.6825 / 0.508 / 0.314 / 0.2223–0.2226 bar.
  ρ: 1.550 / 1.118 / 0.889 / 0.606 / 0.452. ρ envelopes: 1.515–1.584, 1.091–1.140, 0.867–0.907, 0.583–0.622,
  0.429–0.464. All agree with the doc to its printed precision. The one rounding quibble: p at 60 km is 0.2223 with
  log interpolation and 0.2226 with linear, printed as 0.223.
- **§3 wind column, every row:** the same issue as #4. The ±0.5 km bin means use whichever probes happen to have a
  sample in the bin. The 60 km value 85 is a 2-probe mean (Large 91.2, Night 79.4); interpolation gives 3 probes
  and 84.6 (77.4–91.3). Interpolated 4-probe means are 60.1 / 61.9 / 63.4 / 74.0 / 84.6 m/s at 50/53/55/58/60 km,
  against the doc's 60 / 63 / 65 / 76 / 85. Envelopes: 52.8–68.3, 54.8–70.0, 59.1–72.7, 66.3–84.3, 77.4–91.3. The
  doc's means run 0–2 m/s high. This is well inside the ±10 m/s [Y] band, but the "four-probe mean" wording is not
  accurate for the wind.
- **`A_00_index.md`** says the PV probes span "4.4°N–59.3°N". The source (#8) gives Day 31.3°S and Night 28.7°S.
  docs/25 is right and the index is wrong.
- **§5.1, Venera 11–14 peak g:** Dutta Table 1 gives "138-167" g and "-18 to -21" for each of Venera 11–14, with
  no pairing between them. Assigning 138 g to −18° and 167 g to −21° is the session's own pairing (plausible, but
  [Y]).
